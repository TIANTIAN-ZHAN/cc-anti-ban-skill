# Claude 自查清单与申诉准备

[返回产品介绍](../README.md) · [Skill 入口](../SKILL.md) · [来源与证据限度](self-check-sources.md)

这是一份给用户和独立 Coding Agent 使用的文字工作清单。它帮助辨别问题、整理已有信息和选择下一步；不判断官方封禁原因，不生成账号风险分，也不修改 CLI 的 Report。

## 先分清这次问题

先看用户已经给出的错误摘要、发生时间和使用入口。若足够，直接推进；不再索要同一信息，也不用答完所有条目。

| 当前主要现象 | 优先去哪里 |
| --- | --- |
| 连接超时、TLS/代理错误、命令无法启动 | 相关环境条目；仅在已有授权范围内做本地检查 |
| 登录、认证、权限或模型不可用提示 | 先区分客户端和认证类别，结合具体错误；单个 403 不足以认定封号 |
| 用量、额度、支付、订阅或身份验证提示 | 用户在官方页面核对对应提示，Agent 整理脱敏摘要 |
| 明确的账号停用/限制通知 | 准备官方复核材料；无需先做网络探测来“证实封号” |
| 信息不足或相互冲突 | 保留未确认，只问能改变下一步的一两个缺项 |

只问类别，不收凭据。例如“是在浏览器、官方客户端、Claude Code 还是第三方客户端？使用订阅登录、API key 还是组织管理的认证？”不需要用户名、邮箱、key 值或完整登录链接。错误原文可由用户去掉标识与凭据后提供。

## 七类条目，按相关性选择

| 条目 | 需要时核对什么 | 来源和处理边界 |
| --- | --- | --- |
| 1. 错误类型 | 连接、认证/权限、额度、KYC，还是明确停用；首次出现时间、时区、可复现方式 | 保留原始提示的脱敏摘要，不把所有“用不了”归为封号 |
| 2. 客户端与认证 | 当前入口、认证类别、是否组织管理；本次是谁在操作客户端 | 只收类别，Claude 是对象，由独立 Agent 协助；第三方客户端身份不等于官方授权已核 |
| 3. 本人真实地区与资格 | 问题相关时，由用户核对本人真实国家/地区及适用产品的官方支持范围 | 不靠第三方 IP 标签代替真实所在地，不把换节点当成取得使用资格 |
| 4. 最近相关变化 | 设备、国家、节点、客户端、启动方式是否在故障前后发生变化；记录大致时间 | 是排查线索，不是扣分项；正常同城/上下班换网本身不能被写成异常或封禁原因 |
| 5. 当前启动代理 | 相关时复用本工具的本地安装、配置、代理选择/冲突证据 | 先有本地读取授权；不读取真实配置来完成纯文字自查。显式 HTTP(S) 代理不等于人人必须全局＋TUN |
| 6. 支付、KYC、订阅、用量 | 用户在官方页面看到哪类提示、是否仍待本人处理 | 本人处理验证与付款，只回传脱敏状态；不收证件/卡号，不自动升级订阅或多号轮换 |
| 7. 下一步选择 | 已有证据够不够，需要人工核对、获准参考探测，还是官方申诉准备 | 不为凑齐报告强制外联；无法判断就保留未知。明确停用优先官方复核 |

只展开会影响当前判断的条目。纯安装直接走 [INSTALL.md](../INSTALL.md) 并停在构建和 `--help`；不要求安装用户完成此清单。与问题无关的条目可以省略，需说明时标“不适用”。

## 每一项写清它是什么证据

| 状态 | 含义 |
| --- | --- |
| 用户自述 | 用户描述或用户提供的脱敏材料转述；写明来源、时间和未核处 |
| 工具观察 | 本工具在授权范围内实际取得的结果，或已有本工具脱敏报告中的观察；注明执行/报告时间与范围，不冒充当前实时结果 |
| 未确认 | 未执行、缺少证据、来源不明或不同信息有冲突 |
| 不适用 | 与本次问题无关或该项不适用于当前入口；给简短理由即可 |

用户说“我在官方页面确认了”仍标用户自述，并记录其描述。不要自行写成“已通过官方验证”。用户主动提供的 Net.Coffee 等第三方报告单列为“用户提供的第三方材料（站点、时间、摘要）”；它不是本工具观察或 Anthropic 的账号判定，不并入 CLI 数字评分。

交付一个短结论，再列与本次问题有关的条目即可：

| 条目 | 状态 | 脱敏依据及时间 | 下一步 |
| --- | --- | --- | --- |
| [相关条目] | [四种状态之一] | [已提供什么；未提供写未确认] | [最小必要动作或无需动作] |

同时区分“已有证据”“可能原因”“仍不知道什么”。不要用看似精确的账号分数替代未知，也不要把安装/探测通过或 HTTP 200/401/403/404 转译为账号正常。核心 `account` 仍为 unknown、零通过权重，人工清单不写回原 Report。

## 只在需要时进入实际环境检查

检查已有脱敏报告可先读 [报告契约](report-contract.md)。确需读取本机时，遵循当前授权、[安装入口](../INSTALL.md) 和 [隐私范围](safety-and-privacy.md)。本地读取可能接触完整环境与用户 settings 中的凭据，不要用“只看分数”省略告知。

参考探测、新 Claude 会话及第三方检测站是不同操作，不能互相代替授权。现有工具仅在预览固定清单后单次执行参考探测；第三方检测页面可能自动运行 IP/DNS/WebRTC/设备检测，看到参考卡不等于已经同意运行。用户不选择这些动作时，交付文字判断与未确认项即可。

## 明确停用时准备什么

使用 [官方申诉入口说明](https://support.claude.com/en/articles/8241253-safeguards-warnings-and-appeals)。KYC 提示则由本人按 [官方身份验证说明](https://support.claude.com/en/articles/14328960-identity-verification-on-claude) 处理，不把身份验证自动等同账号停用。

以下模板仅用于准备材料；删掉不相关项，未知内容不要补造。账号标识由本人在官方表单填写，无需提供给本 Skill。

```text
主题：请求复核账号限制

现象与首次时间（含时区）：[脱敏描述]
官方页面/通知的提示：[脱敏摘要；未提供则注明]
使用入口与认证类别：[相关时填写，不含凭据]
本人实际国家/地区：[仅在相关时填写，不用代理出口代替]
故障前后的相关变化：[时间线；不确定写未确认]
已有自查：[动作、时间、结果及来源；未执行不要写通过]
希望核查的问题：[请求解释或复核具体限制]
```

不自动添加“确认无违规”“已完成 KYC”或“环境完全正常”等用户未提供、工具也未证明的断言。没有明确发送或提交授权时，只交草稿和官方入口，不联系 Support、不提交表单、不代替用户付款或验证身份。
