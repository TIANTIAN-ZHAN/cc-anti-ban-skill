# 环境报告约定

这是一份开发约定，尚无真实报告生成器或评分实现。它约束未来适配器与当前证据审阅，避免界面将未知状态变成正常。

## 最小字段

| 字段 | 含义 |
| --- | --- |
| `mode` | `demo` 或 `evidence-review`；真实适配器实现并验证前不使用 live 模式 |
| `observed_at` | 证据观察时间；未知为 `null`，不能用页面打开时间冒充采样时间 |
| `score.value` | 唯一总分；当前真实环境审阅必须为 `null` |
| `score.policy` | 可追溯的策略版本；尚未定义为 `null`，演示为 `demo-v1` |
| `checks` | 每项的观察事实、来源、状态、影响和验证建议 |
| `coverage` | 总项数、已观察项数、未知项与不支持项；不得将未知纳入通过数量 |
| `repair_plan` | 待确认的具体调整、范围、代价、备份/回滚办法及复测标准 |
| `before` / `after` | 相同检查集合下的对比；没有真实复测时 `after` 为 `null` |
| `limitations` | 证据缺口、条件变化与不可比较项 |

检查状态：`normal`（有证据支持）、`attention`（存在与目标相关的具体问题）、`unknown`（证据不足/未执行）、`unsupported`（能力尚不支持）。仅凭用户提供的信息只能陈述该材料支持的范围。

操作状态：`proposed`、`confirmed`、`applied_unverified`、`verified`、`failed`、`rolled_back`、`not_executed`。用户确认后不能跳过执行和验证证据直接标 `verified`。

## 初始化版真实请求示例

用户说“检查我的环境，确认后帮我修复”时：说明尚无真实适配器；可整理已有脱敏证据与计划。总分显示“未评分”，`score.value` 与 `score.policy` 为 `null`，未知检查保留 `unknown`，真实修复保持 `proposed` / `not_executed`，`after` 为 `null`。不打开演示后声称用户环境有 83 分或必然存在两项问题。

## 演示专用

`demo-v1` 仅用于页面交互：基础分 100，DNS 示例项减 7，WebRTC 示例项减 5，UDP 未知暂预留 5。初始 83；选中 DNS 的模拟复测为 90；两项均处理后为 95。UDP 仍为未知。该权重不用于真实环境，也不与站方评分进行数值比较。

同条件复测至少保持检查集合和实现/策略版本一致，记录允许的时间间隔、浏览器与出口/网络条件是否变化。采样目标、次数、超时和额度上限应由后续适配器明确；本版不默认授权任何请求。
